# Privacy

Frame is a developer tool. We respect your privacy and try to be transparent about what we collect.

## What we collect

When analytics is enabled (the default — opt-out via Settings), Frame sends a small set of anonymous usage events. Every event carries only its name plus, where noted, a property whose value comes from a **fixed list** — never free text, never anything typed or generated by you.

Alongside each event go four things and nothing else: a **random install ID** (see below), your **app version**, your **operating system** (`darwin`, `win32`, `linux`), and your **approximate location** (see below).

The complete event list:

| Event | Property (fixed values only) | What it tells us |
| --- | --- | --- |
| `app_started` | — | the app was launched |
| `project_initialized` | — | a Frame project was set up |
| `spec_created` | `origin`: `button` / `agent` / `conductor` | a spec was created, and how it was started (Frame's New Spec launcher, asking an agent directly, or an orchestration run; absent when Frame cannot tell) |
| `spec_phase_advanced` | `phase`: `draft` / `specified` / `planned` / `tasks_generated` / `implementing` / `done` | the spec workflow is being used |
| `agent_run_started` | `tool`: `claude` / `codex` / `gemini` / `custom` | an AI CLI was launched (identity of custom tools is never sent — they all read as `custom`) |
| `orchestrator_opened` | — | the orchestrator view was opened |
| `orchestration_run_started` | — | a parallel orchestration run began |
| `plugin_toggled` | `action`: `enabled` / `disabled` | the plugin system is being used (never which plugin) |
| `ai_tool_selected` | `tool`: `claude` / `codex` / `gemini` / `custom` | the active AI tool was switched, and to which |
| `panel_opened` | `panel`: `decisions` / `structure` / `prompts` / `activity` | which dock panels get used, and which are dead weight |
| `implement_mode_selected` | `mode`: `step-by-step` / `guided` / `autonomous` / `custom` | how people prefer to run a spec's implementation |
| `tour_finished` | `outcome`: `finished` / `skipped` | whether the first-run tour lands or gets dismissed |
| `session_resumed` | — | the resume-a-session path was used (never which session) |
| `task_completed` | — | a task was marked done (never its title, id, or project) |
| `settings_changed` | `setting`: `analytics` / `error_reporting` / `crash_dumps` / `ui_zoom` | which setting was touched — never the value it was set to |
| `feedback_submitted` | `channel`: `github_issue` / `github_discussion` / `email` | which route carried an in-app feedback report — never its title, description, or the diagnostics shown in the form |
| `error_occurred` | `category`: a fixed list of failure types (e.g. `agent_cli_not_found`, `orch_merge_failed`) | what breaks in the wild — counts only, never error messages, stack traces, or file paths |

This list is enforced in code: events and property values outside this registry are dropped before anything is sent. Any addition to the list will be reflected here first.

This is enough for us to understand how many people use Frame, which features get used, whether new users activate, what fails most often, and which platforms / versions are in use.

## The install ID

Each install generates a **random ID** the first time it sends anything — a UUID, produced by your machine's random number generator and nothing else.

- It is **not** derived from your hardware, your machine name, your username, your email, or anything else about you. Two installs on the same computer get different IDs.
- It lets us tell one install from another, which is the only way to count actual users rather than launches, see whether people come back, and find where they get stuck.
- It is stored in Frame's own settings file on your machine and sent with each event. Nothing we hold can connect it to a person.
- **Turning analytics off deletes it.** Turning analytics back on generates a new one — the old one is not recoverable, by us or by you.

## Approximate location

Each event is tagged with the **country and region** it came from, worked out from the IP address of the request.

- We use it to see which parts of the world Frame is used in, so documentation, defaults and support hours can follow real usage rather than guesswork.
- It is **country and region level** — the same granularity a weather site infers. No city-block accuracy, no GPS, no street address.
- **The IP address itself is not stored.** PostHog resolves it to a location on arrival and discards it; it is never written to the event, and we never see it.
- Turning analytics off stops this like everything else — no event, no location.

## What we do **not** collect

- ❌ File paths
- ❌ File contents or code
- ❌ Project names
- ❌ AI prompts or responses
- ❌ Terminal input or output
- ❌ Email addresses, names, or any personally identifiable information
- ❌ Your IP address — it is used to derive country and region on arrival, then discarded, never stored
- ❌ Precise location — no GPS, no street-level or city-block accuracy
- ❌ Screen recordings or session replay of any kind

## How to opt out

Open **Settings** (`Cmd+,` on macOS, `Ctrl+,` on Windows/Linux) and toggle **"Send anonymous usage stats"** off. The setting takes effect immediately and persists across launches, and switching it off deletes the install ID at the same moment.

Your opt-out is durable: if the settings file on disk is ever corrupted beyond repair, analytics **fails closed** — Frame records it as switched off, nothing is sent, and no install ID is kept. Corruption can never silently re-enable analytics.

You can also dismiss the one-time notice card — that doesn't change the setting itself, only hides the card. If what we collect changes materially, the card reappears once with the new text, even if you dismissed the previous one.

## Error reports (opt-in, off by default)

Separately from usage stats, Frame can send **crash and exception detail** so bugs can be diagnosed instead of merely counted. This is **off unless you turn it on**, under **Settings → Privacy & Analytics → "Send error reports"**, and it also requires anonymous usage stats to be on.

When it is on, an exception's message and stack are sent after two passes:

- **Secret redaction** — the same scrubbing the local log file uses: API keys (`sk-…`), GitHub/Slack tokens, AWS keys, JWTs, `Bearer` headers, and `password=`/`token=`/`api_key=` values become `[REDACTED]`.
- **Path stripping** — every absolute path is reduced to its filename. `open '/Users/you/your-startup/src/billing.js'` is sent as `open 'billing.js'`. The filename says which file broke; nothing says who you are or what you are building.

This channel never touches the event list above, and nothing on it is sent while the toggle is off.

## Where the data goes

Analytics is sent to [PostHog](https://posthog.com), an open-source product analytics service, on their **EU cloud** (`eu.i.posthog.com`). PostHog derives country and region from the request IP and discards the IP itself — see **Approximate location** above. PostHog is [self-hostable](https://posthog.com/docs/self-host) and their platform is open source, so what happens to the data is auditable rather than taken on trust.

## Local logging

Frame keeps a **local** log file to make bugs debuggable — it never leaves your machine and is not part of analytics.

- **Location:** Electron's standard logs directory — on macOS `~/Library/Logs/Frame/main.log` (find it via **Settings → About → Open Logs Folder**).
- **Rotation:** capped at 5 MB with up to 3 archived files (`main.old.1.log` … `main.old.3.log`); old content is discarded, never uploaded.
- **Redaction:** every line is scrubbed before it is written. Recognized secret shapes — API keys (`sk-…`), GitHub/Slack tokens, AWS keys, JWTs, `Bearer` headers, and `password=`/`token=`/`api_key=` values — are replaced with `[REDACTED]`. The same redaction applies to the per-project prompt history under `~/.frame/prompts/`.

When filing a bug report, attaching the log is the fastest way to help us help you — skim it first if you want to double-check its contents.

## Activity record (local only)

Frame does a lot of work on its own — watching files, reconciling spec phases, rebuilding its index, recovering a corrupt state file, running hooks during a commit. The **Activity** panel shows that work, and it reads a record kept **on your machine only**. Nothing in it is transmitted, to us or anyone else; it shares no code path and no storage with analytics, and turning analytics off or on changes nothing about it.

- **Location:** `~/.frame/activity/<project>/activity.jsonl`, outside your repository — Frame never edits your project's `.gitignore`, so keeping it in the repo would dirty your `git status`. Work that belongs to no project goes to an `app` bucket.
- **Retention:** the live file rotates at 2 MB into a single archived generation, and any project's record untouched for 7 days is deleted.
- **What a line contains:** an event name, a timestamp, and low-cardinality fields — counts, durations, enum reason codes, a spec slug, and project-relative file paths. There is **no free-form text field**, so no prompt, no file content, no command output and no error message can be recorded. Values still pass through the same redaction the log file uses.
- **Turning it off:** delete the directory at any time. Frame recreates only what happens next, and nothing depends on the old contents.

## Crash dumps (local only)

On a crash, Frame saves a **minidump on your machine** using Electron's built-in crash reporter with uploading **disabled** — nothing is ever transmitted, to us or anyone else. This exists purely so a crash can be diagnosed locally.

- Toggle it off under **Settings → Privacy & Analytics → "Keep local crash dumps"** (takes effect on next launch).
- This is separate from **"Send error reports"** above: minidumps stay on disk whatever that setting says.
